# Module 1 — Problem Discovery and Customer Insight

**Purpose:** Help the founder prove that a specific customer has a meaningful problem before investing heavily in a solution.

**COSA surfaces:** Projects, Strategy, Vault, Tasks, Academy simulations, and Agents.

## Lesson 1.1 — Problem Discovery Framework

**Content:** Start with a customer, situation, painful job, current workaround, and consequence. Founders should begin from observed behavior rather than a product idea.

**COSA practice:** Create a discovery Project and record the first problem statement.

**Learner output:** Write a customer–problem–context statement.

**Learning objectives:**

- Define a problem in terms of a specific customer, context, and consequence.
- Separate observable facts from founder assumptions.
- Create a first problem statement that can be tested with customers.

## Lesson 1.2 — Conducting Qualitative Discovery Interviews

**Content:** Prepare and conduct discovery interviews around past behavior, real situations, current workarounds, and consequences. Do not ask whether people like an idea.

**COSA practice:** Use Vault or a Project template to prepare interview questions and notes.

**Learner output:** Prepare an interview guide with five open-ended questions.

**Learning objectives:**

- Prepare open-ended interview questions that reveal real customer behavior.
- Conduct an interview without leading the participant toward a preferred answer.
- Capture quotes, stories, and behavioral evidence in a structured format.

## Lesson 1.3 — Defining a Target Customer Segment

**Content:** Define a target segment by shared context and behavior, not only demographics. Choose people who are most likely to experience the problem frequently and urgently.

**COSA practice:** Record target-segment assumptions in Project or Strategy.

**Learner output:** Define one narrow initial customer segment.

**Learning objectives:**

- Identify the customer segment with the strongest and most urgent problem.
- Describe a segment using behavior, context, and constraints instead of demographics alone.
- Prioritize one initial segment for discovery work.

## Lesson 1.4 — Using Jobs to Be Done

**Content:** Jobs to Be Done describes the progress customers seek. Cover the functional, emotional, and social dimensions that shape a customer decision.

**COSA practice:** Create a customer-job template in Vault or Strategy.

**Learner output:** Write one Jobs-to-Be-Done statement.

**Learning objectives:**

- Explain the difference between a customer profile and a customer job.
- Identify functional, emotional, and social dimensions of a customer job.
- Write a Jobs-to-Be-Done statement for an early venture idea.

## Lesson 1.5 — Distinguishing Real Problem Signals from Assumptions

**Content:** Contrast evidence with opinion. A painful recent event, an expensive workaround, lost time, lost money, or a request for help is stronger than “I would use that.”

**COSA practice:** Tag research notes as observation, quote, assumption, or evidence gap.

**Learner output:** Classify ten research statements into evidence or assumption.

**Learning objectives:**

- Recognize the difference between opinions, intentions, and observed behavior.
- Identify signals that indicate urgency, frequency, and willingness to change.
- Reject weak evidence before it influences a product decision.

## Lesson 1.6 — Documenting and Classifying Problems

**Content:** Teach a lightweight problem record: customer, situation, job, pain, workaround, consequence, and confidence level. Consistent documentation makes research comparable.

**COSA practice:** Store and organize problem records in Vault or Project knowledge.

**Learner output:** Document three problem records using one consistent template.

**Learning objectives:**

- Document customer problems in a consistent and reusable format.
- Classify problems by severity, frequency, and affected segment.
- Build a problem repository that supports later prioritization.

## Lesson 1.7 — Testing a Problem Hypothesis

**Content:** A useful hypothesis can be wrong. State a testable belief, define what would support or weaken it, then choose a small experiment before building a product.

**COSA practice:** Add a problem hypothesis and evidence criteria to the Project.

**Learner output:** Create one falsifiable problem hypothesis.

**Learning objectives:**

- Form a falsifiable problem hypothesis.
- Define the evidence needed to support or reject the hypothesis.
- Decide whether to continue, revise, or stop an investigation.

## Lesson 1.8 — Synthesizing Interview Insights

**Content:** Turn individual notes into patterns by grouping quotes, identifying repeated events, noticing contradictions, and avoiding conclusions based on one loud participant.

**COSA practice:** Use Vault, Agents, or a research template to cluster interview themes.

**Learner output:** Produce a one-page insight summary with three recurring patterns.

**Learning objectives:**

- Group interview findings into themes without losing customer context.
- Identify repeated patterns across multiple conversations.
- Turn raw interview notes into actionable problem insights.

## Lesson 1.9 — Preparing for Solution Validation

**Content:** Close discovery by reviewing what is known and what remains uncertain. The next step is not a large build; it is testing whether a proposed solution creates meaningful value.

**COSA practice:** Create a decision note and next-step tasks for solution validation.

**Learner output:** Write a discovery summary and one solution-validation question.

**Learning objectives:**

- Summarize the strongest validated problem evidence.
- Define the assumptions that remain uncertain before building a solution.
- Select the next experiment for solution validation.
