# Module 2 — Solution Design and Early Validation

**Purpose:** Help the founder design the smallest useful solution experiment and learn whether customers experience real value.

**COSA surfaces:** Strategy Canvas, Project Roadmap, Vault, Templates, Tasks, and Agents.

## Lesson 2.1 — Solution-Fit Framework

**Content:** Connect a customer problem, proposed solution, behavior change, and measurable outcome. Features are not strategy unless they test a meaningful customer assumption.

**COSA practice:** Map one problem to one proposed customer outcome in Strategy.

**Learner output:** Create one solution hypothesis.

**Learning objectives:**

- Explain the relationship between customer problem, proposed solution, and expected outcome.
- Identify the assumptions behind a proposed solution.
- Define a solution hypothesis that can be tested quickly.

## Lesson 2.2 — Designing a Minimum Viable Product

**Content:** An MVP is the smallest experience that tests the riskiest assumption. It can be a manual service, prototype, concierge workflow, landing page, or limited product—not necessarily a coded application.

**COSA practice:** Scope an MVP in Project tasks and a simple roadmap.

**Learner output:** Define the MVP boundary: included, excluded, and assumption tested.

**Learning objectives:**

- Define an MVP as the smallest testable experience, not the smallest product.
- Prioritize features that test the riskiest assumption first.
- Create an MVP scope that can be delivered within a short experiment cycle.

## Lesson 2.3 — Running Solution Tests

**Content:** Select the right test: prototype review, concierge test, landing-page test, pre-order conversation, or usability session. Every test needs a decision rule before it begins.

**COSA practice:** Create an experiment task list and a success criterion.

**Learner output:** Build one test plan with hypothesis, method, audience, and decision rule.

**Learning objectives:**

- Choose a suitable test method for a solution hypothesis.
- Define a success criterion before running an experiment.
- Interpret test results without rationalizing weak evidence.

## Lesson 2.4 — Conducting Prototype Feedback Interviews

**Content:** Prototype feedback should reveal behavior, comprehension, and hesitation. Observe what users do instead of asking whether they like the prototype.

**COSA practice:** Save prototype interview notes and feedback themes in Vault.

**Learner output:** Prepare a prototype interview script and observation checklist.

**Learning objectives:**

- Design a prototype interview that focuses on behavior rather than compliments.
- Observe where participants understand, hesitate, or reject a solution.
- Capture feedback that can guide the next prototype iteration.

## Lesson 2.5 — Evaluating Product-Solution Fit

**Content:** Product-solution fit is early evidence that a solution helps a specific customer solve a meaningful problem. It is not yet proof of market demand, pricing, or scalable growth.

**COSA practice:** Review customer feedback and update the Project decision log.

**Learner output:** Rate the current solution evidence as strong, mixed, or weak.

**Learning objectives:**

- Assess whether a proposed solution addresses a meaningful customer problem.
- Compare customer reactions across different segments.
- Identify the strongest evidence of early product-solution fit.

## Lesson 2.6 — Mapping Competitive Alternatives

**Content:** Customers compare a startup with direct competitors, indirect competitors, spreadsheets, employees, manual habits, waiting, doing nothing, or an internal build.

**COSA practice:** Add alternatives and differentiators to the Strategy workspace.

**Learner output:** Build a comparison of three customer alternatives.

**Learning objectives:**

- Identify direct competitors, indirect competitors, and current customer workarounds.
- Explain why customers may choose an alternative to a new product.
- Position a solution against the most relevant alternative.

## Lesson 2.7 — Articulating a Core Value Proposition

**Content:** Express value in customer language: for whom, what outcome, why now, and why this option is better than the current alternative.

**COSA practice:** Draft and review a value proposition in Strategy or Marketing.

**Learner output:** Write one value proposition and one proof point.

**Learning objectives:**

- Write a clear value proposition for a specific customer segment.
- Connect product capability to a meaningful customer outcome.
- Test whether the value proposition is understandable and differentiated.

## Lesson 2.8 — Synthesizing Solution-Fit Evidence

**Content:** Gather prototype results, feedback, objections, and observed behavior into one decision-ready view. Focus on what is known, what is weak, and what to test next.

**COSA practice:** Create a solution-validation summary in the Project knowledge base.

**Learner output:** Produce a one-page solution-fit evidence summary.

**Learning objectives:**

- Organize prototype, interview, and experiment findings into a solution-fit summary.
- Identify unresolved risks before committing more resources.
- Recommend the next validation decision based on evidence.

## Lesson 2.9 — Preparing for Business-Model Validation

**Content:** A helpful solution still needs a viable business model. Move from “Does this help?” to “Who pays, how much, through which channel, and at what cost?”

**COSA practice:** Open Sales, Finance, and Marketing to preview the next learning module.

**Learner output:** List three business-model assumptions to test.

**Learning objectives:**

- Define the commercial assumptions that must be tested next.
- Identify the customer behavior that indicates willingness to pay.
- Prepare a transition from solution testing to business-model testing.
