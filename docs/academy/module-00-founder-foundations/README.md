# Module 0 — Founder Foundations: From Idea to Operating Rhythm

**Purpose:** Help a founder turn an unclear idea into one focused project, one 12-week direction, and one weekly operating rhythm.

**COSA surfaces:** Hologram Hub, Dashboard, Projects, Strategy, 12-Week Year, OKRs, Tasks, Approvals, Agents, Vault, Academy.

## Production storyboard

The detailed, 30-second-ready storyboards are in [production/README.md](production/README.md). Each lesson has one storyboard file, divided into ten clips that can be created and edited independently.

## Lesson 0.1 — Welcome to COSA: Your Founder Operating System

**Content:** COSA is a founder operating system rather than a collection of tools. Introduce Hologram Hub, Projects, Strategy, OKRs, 12-Week Year, Tasks, Approvals, Agents, Vault, Sales, Marketing, Finance, Legal, Workflows, and Academy. Explain the journey: learn, define a project, validate assumptions, run an execution cycle, review evidence, and decide the next move.

**COSA practice:** Take a guided tour of Hub, Dashboard, Academy, Strategy, Tasks, and Approvals.

**Learner output:** Choose one learning path: idea stage, validation stage, customer stage, or operating stage.

**Learning objectives:**

- Identify the main COSA capabilities and the founder decisions they support.
- Navigate the learning roadmap from an idea to scalable operations.
- Choose a learning path based on the current maturity of a venture.

## Lesson 0.2 — What Is a Startup?

**Content:** A startup is an organization searching for a repeatable and scalable way to create value under uncertainty. Distinguish an idea, a project, a startup, and a traditional small business. Explain that progress means stronger evidence and better decisions, not more features or activity.

**COSA practice:** Use founder onboarding to describe a problem, target customer, and venture goal.

**Learner output:** Write: “We believe that [customer] struggles with [problem] in [context].”

**Learning objectives:**

- Explain a startup as an organization searching for a repeatable and scalable business model.
- Distinguish an idea, a project, a small business, and a startup.
- Describe why customer evidence is more valuable than founder assumptions.

## Lesson 0.3 — Startup for a One-Person Company

**Content:** A solo founder does not need to perform every activity manually. The founder remains accountable for customer understanding, strategy, money, risk, and final decisions while using systems and AI for leverage. Introduce a weekly operating loop: choose one project, define an outcome, act, review evidence, then continue, change, or stop.

**COSA practice:** Explore Hub, Tasks, Agents, and Approvals as a human-led operating system.

**Learner output:** List three founder-owned responsibilities and three activities that can be AI-assisted.

**Learning objectives:**

- Explain how a solo founder can use systems and AI without giving up accountability.
- Separate founder-owned decisions from AI-assisted activities.
- Design a simple weekly operating loop for a one-person company.

## Lesson 0.4 — From an Idea to a Project

**Content:** A Project is a focused venture bet, not a generic task list. It contains a problem, target customer, current hypothesis, desired outcome, and next learning actions. Distinguish workspace, project, task, evidence, and Academy learning output.

**COSA practice:** Create or inspect a Project in Strategy and connect it to its tasks.

**Learner output:** Produce a project brief with title, target customer, problem, and near-term outcome.

**Learning objectives:**

- Define a project as a focused venture bet rather than a list of tasks.
- Distinguish workspace, project, task, evidence, and Academy learning output.
- Create a clear project brief for an early-stage opportunity.

## Lesson 0.5 — The Project Lifecycle: Learn Before You Scale

**Content:** Teach the project lifecycle as a sequence of questions: is the problem real, does the solution help, will customers pay, can a pilot work, can demand repeat, and can the organization scale? Projects advance through evidence and decisions—not elapsed time, course completion, or founder desire.

**COSA practice:** Review Project Roadmap, validation views, stage context, and project review screens.

**Learner output:** Identify the current project phase and write its most important unanswered question.

**Learning objectives:**

- Explain the purpose of each major phase in a startup project lifecycle.
- Identify the key question that should be answered in the current project phase.
- Recognize that learning completion does not replace real-world evidence.

## Lesson 0.6 — Your First 12-Week Year

**Content:** The 12-Week Year is a focused operating rhythm, useful when a founder has enough clarity to commit to an outcome. Highly uncertain projects may first need two- or four-week validation cycles. A healthy cycle has a theme, one or two outcomes, weekly commitments, review rhythm, and an adjustment rule.

**COSA practice:** Open 12-Week Year, weekly review, next actions, and the WY Loop.

**Learner output:** Draft one 12-week theme, one outcome, and three first-week actions.

**Learning objectives:**

- Explain when a 12-week operating cycle is useful for a startup.
- Translate a strategic direction into one measurable 12-week outcome.
- Create a first-week action plan that supports the selected outcome.

## Lesson 0.7 — OKRs for Early-Stage Founders

**Content:** OKRs are focus and learning tools, not corporate reporting theater. Explain how a Project gives context, an Objective gives direction, Key Results measure outcome, a 12-week cycle gives rhythm, and Tasks drive execution. Early-stage founders should keep this system deliberately small.

**COSA practice:** Create one Objective and connect it to a Project and weekly execution.

**Learner output:** Draft one Objective and up to three Key Results.

**Learning objectives:**

- Distinguish an objective, a key result, and a task.
- Write an outcome-focused OKR for an early-stage project.
- Connect OKRs to a 12-week cycle and weekly execution.

## Lesson 0.8 — Run Your Week: Tasks, Decisions, Approvals, and AI Workforce

**Content:** Founders should run the week from priorities, not notifications. Tasks move work, Workflows standardize repeatable work, Approvals protect high-impact actions, and Agents assist under human accountability. Introduce the weekly review: what was learned, what changed, what matters next, and what requires a founder decision.

**COSA practice:** Use Tasks, Needs You, Blocked Work, Approvals, Workflows, Agents, and Hub priorities.

**Learner output:** Create three weekly tasks, identify one founder decision, and delegate one safe activity to an AI agent.

**Learning objectives:**

- Prioritize weekly work based on project outcomes rather than incoming requests.
- Distinguish tasks, workflows, decisions, and approvals.
- Use AI assistance while keeping human accountability for important actions.
